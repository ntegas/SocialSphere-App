## Фаза 0 — Фундамент (до первого экрана)

Решения, которые блокируют старт:

1. **Цвет.** Apple-система несёт свой акцент — индиго `#5B53D6` и палитру iOS.
   - Вариант 1 (рекомендуется): полностью перейти на Apple-токены — единый iOS-look везде.
   - Вариант 2 (гибрид): структура Apple, но сохранить бренд `#4F3DC7` и teal у компаний.
   *Выбор фиксируется здесь и применяется ко всем экранам одинаково.*

2. **Тёмная тема.** `AppleAppTheme(darkTheme = …)` переключает light/dark.
   - Обернуть корневой `setContent { AppleAppTheme { … } }` в `MainActivity`.
   - В Настройках — переключатель «Система / Светлая / Тёмная», состояние в `SharedPreferences`
     (не `mutableStateOf` — наше правило против сброса при перезапуске).
   - `CompositionLocalProvider` отдаёт `LocalContext` **и** `LocalConfiguration` (иначе
     `stringResource` не обновится при смене языка).

3. **Типографика.** `AppleAppTheme` использует наш `Type.kt`. Проверить, что размеры/веса
   не конфликтуют с iOS-кеглями (16sp строки, 13sp заголовки секций). Поправить `Type.kt`
   точечно, если нужно — это общий шаг, до экранов.

4. **Фон экранов.** Каждый экран → `GroupedScreen { … }` (фон `groupedBackground`).

**Готовность Фазы 0:** выбран цвет (1/2), тема обёрнута, переключатель работает и переживает
перезапуск, qa зелёный, на устройстве видно light↔dark.

## Обязательный цикл для КАЖДОГО экрана

A. **Чтение.** ТЗ (`SOCIALSPHERE_SPEC_V2.md`) по экрану + **точные текущие строки** кода
   через `sed`/`grep` в том же ходе. Составить **инвентарь функций** экрана (всё, что нельзя
   потерять: действия, переходы, обработчики, состояния).

B. **Макет.** HTML-макет экрана в **двух режимах — light и dark**. Показать, получить «ок».
   Без одобрения макета — код не пишем.

C. **Порт.** Атомарными python-скриптами (assert-якоря + проверка баланса `{}`/`()`),
   по секции/вкладке за раз. Никаких TODO/заглушек. Якоря — только из свежего чтения.

D. **Проверки (все зелёные до ZIP):**
   - `python3 qa_check.py` — зелёный (У41/У42/У49/У50/У51/У52/У53).
   - grep изменённой зоны на хардкод-литералы (латиница/кириллица без `R.string`) → в `strings.xml` ×3 (ru/en/el), `&`→`&amp;`, без дублей `<string name>`.
   - **Инвентарь функций сверён** — ни одна не пропала (роли семьи НЕ локализуем — это данные).
   - один акцент на экран; отступы кратны 4dp; токены только из системы.

E. **Сборка.** Пересобрать ZIP → собрать в Android Studio → скрин **light и dark** →
   починить отступы/контраст. Устройство — единственный настоящий визуальный тест.

F. **Фиксация.** Отметить экран готовым в этом файле, перейти к следующему. Один экран — один цикл.

## Чего НЕ делаем

- Не переделываем несколько экранов в одном ходе и не «вслепую».
- Не пишем код без одобренного макета.
- Не используем память/старые view как якоря — только свежее чтение.
- Не трогаем заблокированный стек (AGP 8.5.2 / Kotlin 2.0.21 / KSP / Gradle 8.9 …).
- Не плодим старые пакеты `com/example/`; не возвращаем убранные элементы.
