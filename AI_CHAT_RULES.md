**Контрольный список — выполнять ПИСЬМЕННО и ДО действия:**
1. **Читать прямо сейчас.** Перед каждой правкой — `sed/grep` точных строк-якорей в ТЕКУЩЕМ файле в этом же шаге. Якоря строить ТОЛЬКО из свежего вывода, не из памяти и не из старых просмотров. Состояние файла могло измениться.
2. **Если assert упал — СТОП.** Не угадывать якорь повторно. Перечитать реальный фрагмент и только потом править. (Дважды за сессию скрипт падал и не писал — это сигнал «перечитай», а не «подбери ещё раз».)
3. **Реестр ограничений.** Перед UI-правкой выписать явные «делать/не делать» из последних сообщений пользователя и сверить изменение с ними (пример: «убрать стрелки» — значит не возвращать никакие шевроны).
4. **Сохранность функций.** Нельзя переписывать блок целиком, не перечислив ВСЕ функции/строки старого блока и не подтвердив, что каждая сохранена. (Большие rewrite запрещены п.6.)
5. **Анти-хардкод.** После UI-правки — grep изменённого участка на строковые литералы (лат/кир) без `R.string`; найдено — заменить на ресурс ×3 языка.
6. **Анализ-первым для дизайна/макета.** До макета/порта: цель → текущие функции ИЗ КОДА (не из памяти) → чеклист покрытия по FUNCTION_INVENTORY → состояния (пусто/правка/ошибка). Показать этот анализ пользователю.

**Мини-формула каждой правки:** прочитал точные строки → выписал ограничения → атомарный скрипт с assert+баланс → qa зелёный → grep на хардкод → отчёт «что сохранено».

## 1. Рабочий цикл (нарушение = повтор старых ошибок)

1. **Один шаг = одна вещь.** Никаких «заодно».
2. **Сначала читай реальный код** (project_knowledge_search / файлы), потом пиши. Не предполагай — проверяй: сигнатуры, имена enum-значений, состав object'ов, что private/public.
3. **Правки — атомарным python-скриптом** с `assert old in s` на каждую замену и проверкой баланса `{}` `()` после.
4. **Вставка top-level кода — только по уникальному текстовому якорю.** Никогда по `rfind('}')` — найдёт не ту скобку (урок 41).
5. **`python3 qa_check.py` перед каждым ZIP** — все проверки зелёные или не выдавай.
6. Среда без Android SDK не компилирует. **Первая `e:`-строка из лога пользователя важнее любых статических догадок.** Цикл: сборка → первая ошибка → фикс → сборка.
7. Пользователь собирает **последний** ZIP в чистую папку. Перед установкой APK — **удалить старое приложение** (drift-классы в старом dex дают ложные крэши, урок 42).

## 3. Запрещено всегда (из SOCIALSPHERE_RULES)

`Icons.AutoMirrored.*` · `enum.name` в UI (только `.label()`) · `!!` · `resolveActivity()` · `database!!` · хардкод строк при наличии ключа · `mutableStateOf` для настроек (только PersistedMutableState) · `LocalDate.now().toString()` для datetime-полей · пустые `onClick = {}` / `onCheckedChange = {}` (обманка хуже отсутствия) · `kotlinOptions` (только `kotlin { compilerOptions }`).

## 4. Архитектурные инварианты (наработаны и проверены)

- **Интенты** — только через `ExternalActionHandler.startIntentSafely` (локализованный контекст ≠ Activity; прямой startActivity молча падает).
- **Bottom nav** — гибрид: `popBackStack(route, inclusive=false, saveState=true)` для вкладок в стеке, navigate+restoreState для новых (restoreState на стартовую вкладку = no-op баг).
- **Дни рождения** — в отображении только через `effectiveDate()` (utils/CalendarUtils.kt); сырые даты прошлого невидимы навсегда.
- **lastContactDate** — date-only `.take(10)` при записи И при чтении; лейбл «Последняя активность», не «общались».
- **Размеры** — только `AppStateStore.setSizeInfo()` (синхронизирует 3 места); заметки — `updateNote` НЕ трогает lastContactDate.
- **Тяжёлые filter/sorted/groupBy** — в `remember { derivedStateOf }`; пер-строчные — с ключом `remember(id)`.
- **Настройки** — каждый контрол пишет в AppSettings (PersistedMutableState) и что-то реально меняет, иначе контрол удаляется.
- **FilterChipsRow** — передавай `onSelect`/`onSelectMultiple`, без них выбор не покидает композабл.
- **Manifest** — `configChanges` на MainActivity не удалять (поворот стирал формы).
