# SocialSphere — ДИЗАЙН-ПРОМПТ (v2, обязательный)

> Вставлять в начало КАЖДОГО чата. Применять при ЛЮБОМ изменении — не только когда
> просят «сделай красиво». Дизайн здесь = всё: UX, логика, расположение и поведение
> кнопок, как они открываются, состояния, эргономика, визуал. Цель — уровень Apple:
> интуитивно настолько, что подсказки не нужны. Сначала думаем — потом код.

---

## 0. Мандат (нерушимое правило)
1. **Каждое** изменение обязано оставлять дизайн ЛУЧШЕ, чем был. Если правка ухудшает
   UX или ломает единообразие — она не готова.
2. Не добавляй «затычки» и технические подпорки в UI (крестики/плюсики/«карандаши»
   на каждом элементе, «Нет данных»). Если тянет так сделать — стоп, это сигнал
   выбрать правильный паттерн (ниже).
3. Перед кодом — короткий разбор: цель, точка входа, поток, состояния, развилки.
4. Эталон — Apple Human Interface Guidelines: **Clarity, Deference, Depth**.
   Контент главный, интерфейс тихий; глубина через слои и плавность, а не украшения.

---

## 1. ГЛАВНЫЙ ПАТТЕРН — режим «Просмотр / Изменить» на КАЖДУЮ вкладку
Точно как «Контакты» на iOS. Это основа всего редактирования в карточке контакта и компании.

### Просмотр (по умолчанию)
- Вкладка **чистая, только для чтения**. Никаких ×, +, карандашей, рамок полей.
- Показываются **только заполненные** поля/блоки. Пустые — НЕ показываются
  (никаких «Нет данных», никаких серых заглушек).
- Читается как готовая карточка: тихий заголовок блока (secondary, labelMedium),
  под ним значения (bodyMedium/Large). Воздух, выравнивание.
- Тап по значению делает **естественное** действие: телефон — звонок, адрес — карта,
  имя родственника — переход. Не редактирование.

### Изменить
- В правом верхнем углу вкладки — **одна** кнопка-текст **«Изменить»** (iOS-стиль,
  без карандаша). Единственная точка входа в правку всей вкладки.
- Тап → вся вкладка редактируется **на месте** (инлайн):
  - заполненные поля становятся полями ввода там же, где стояли;
  - под каждым списком — тихая строка «Добавить телефон» и т.п. (зелёный «＋»
    слева + подпись), **только** в этом режиме;
  - удаление — маленький красный «－» слева (iOS-стиль), **только** в правке;
    по тапу — подтверждение, ничего не теряем молча;
  - пустые блоки, скрытые в просмотре, здесь — как точки ввода: так выявляются все
    возможности вкладки.
- Кнопка справа сверху меняется на **«Готово»** (сохранить и выйти). Слева —
  **«Отмена»** (откатить правки этой сессии).
- Переход просмотр↔правка — плавный (короткий fade/expand, без скачков).

### Уровень — ВКЛАДКА, не весь контакт и не отдельный элемент
- Правка включается на **конкретную вкладку** (у каждой свои функции).
- Нет отдельного экрана ради мелкой правки. Большой «Редактировать контакт» можно
  оставить как расширенную правку, но повседневное — инлайн по вкладкам.

## 2. ЗАПРЕЩЕНО (то, что было плохо)
- ❌ Крестики/плюсики/иконки-действия на каждом элементе **в просмотре**.
- ❌ Иконки-«карандаши» как способ правки. Правка — через «Изменить» вкладки.
- ❌ Большие текст-кнопки ради правки посреди просмотра. В просмотре их нет.
- ❌ «Нет данных»/пустые заглушки. Пусто = не показываем (способ добавить даёт «Изменить»).
- ❌ Пять одинаково ярких кнопок. Один акцент на экран.
- ❌ Скрытые, ничем не обозначенные функции. Всё доступное обязано выявляться.
- ❌ Несогласованность: одинаковое действие выглядит/стоит по-разному на разных экранах.

## 3. Эргономика и поведение (как, где, почему)
- Расположение по iOS: «Назад» — верх-лево; «Изменить/Готово» — верх-право;
  создание в списке — FAB снизу-право.
- Зона большого пальца: частое — ниже/по центру; деструктив/редкое — не на пути.
- Тап-цели ≥48dp, отступ между кликабельными.
- Добавление — в правке строкой «＋ …» → компактный Bottom Sheet (24dp); элемент
  сразу в списке.
- Выбор из многих (контакт, компания) — Bottom Sheet с **поиском** сверху +
  фильтрация + «Создать новый». Один паттерн на всё приложение.
- Дата/время — только Material3 пикеры.
- Клавиатура не закрывает активное поле.
- Авто-заглавная: имена/названия/адрес — по словам; тексты — с заглавной;
  email/логин/поиск/ссылки/индекс — без.

## 4. Визуальная система (держаться токенов)
- Цвет по смыслу: `primary #4F3DC7` — действие/акцент; `tertiary` — даты/события;
  `error` — просрочка/деструктив; `secondary` — второстепенный текст.
- Формы SocialShape: поля/чипы 8, карточки 16, bottom sheet 24, аватары 50%.
- Отступы кратны 4dp (4/8/12/16).
- Типографика: titleMedium — заголовки блоков; bodyMedium/Large — значения;
  labelSmall — подписи. Заголовки секций тихие, не кричащие.
- Сдержанность: один акцент на экран; разделители тонкие или воздух; иконки —
  системные Material, единый размер в ряду.
- Эмодзи — точечно как метка (🎂 💍), не вместо системных иконок действий.

## 5. Состояния и обратная связь
- На вкладку/экран продуманы: просмотр / правка / пусто / загрузка / ошибка /
  нет прав / нет сети. Пусто в просмотре = ничего.
- Успех — мягко: смена состояния + при нужде снэкбар (с «Отмена»).
- Ошибка — человеческим языком.
- Деструктив — только в правке, с подтверждением.

## 6. Движение (Depth)
- Переходы спокойные, стандартные: вкладки — кроссфейд; просмотр↔правка —
  fade/expand; листы — снизу. Глубина через слои, не через тени-обводки.

## 7. Логика и данные (неотделимо от UI)
- Данные ≠ UI-текст: роли/типы — enum, не локализуемые строки.
- Для каждого поля: модель, DAO, реактивность, проставлена ли связь
  (контакт↔событие↔компания), иначе элемент «пропадает».
- Состояние переживает перезапуск; повторное действие не плодит дубли.

## 8. Доступность
- Контраст вторичного текста (вкл. тёмную тему).
- contentDescription у иконок-кнопок.
- Смысл не только цветом (просрочка = цвет + «N дн.»).
- Крупный системный шрифт не ломает вёрстку.

## 9. 8 вопросов ДО кода
1. Цель и сценарий; как пользователь сам это назвал бы?
2. Точка входа: откуда попадёт и как поймёт?
3. Полный поток: вход→ввод→подтверждение→результат→отмена.
4. Все состояния (просмотр/правка/пусто/загрузка/ошибка).
5. Минимум шагов: что предзаполнить/угадать?
6. Обратная связь: успех и ошибка.
7. Край и защита: пустой ввод, дубль, длинный текст, удаление с подтверждением.
8. Переиспользование: какой готовый паттерн взять.

## 10. Самопроверка перед показом
```
[ ] Дизайн стал ЛУЧШЕ; единообразие цело.
[ ] В просмотре вкладка чистая: ни ×, ни +, ни карандашей, ни «Нет данных».
[ ] Правка — одна кнопка «Изменить» на вкладку; внутри всё редактируемо и видно.
[ ] «Готово»/«Отмена» работают; деструктив с подтверждением.
[ ] Назад — лево-верх, Изменить/Готово — право-верх, создание — FAB снизу.
[ ] Один акцент на экран; токены/формы/отступы из системы.
[ ] Тап-цели >=48dp; частое в зоне пальца.
[ ] Переиспользован существующий паттерн.
[ ] Связи в данных проставлены; собралось; qa зелёный.
```

## 11. Процесс подачи
1. Короткий разбор (цель, входы, состояния, развилки) — 3–5 строк.
2. Если развилка — 2–3 варианта с плюсами/минусами и рекомендацией.
3. Реализация по одной вкладке/экрану, делая и просмотр, и правку, с пересборкой
   между.
4. Честно называть компромиссы и что осталось.
