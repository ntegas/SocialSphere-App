## 1. Что это и для кого
SocialSphere — персональный CRM (Android, Kotlin, Jetpack Compose) для тёплого
ведения отношений: вовремя поздравить, заранее купить подарок, помнить кто за
что отвечает, перед встречей за 10 секунд вспомнить главное.
Пакет: `com.aistudio.socialsphere.crmlxb`. Папка модуля: `ss-v1/`.
5 вкладок карточки контакта: **Обзор / Работа / Связь / Подарки / Заметки**.
Языки: ru (основной) / en / el. Владелец активно пользуется приложением с
реальными данными — **потеря данных недопустима**.

## 3. База данных и сохранность данных (критично)
- Сейчас БД `version = 4`, миграции `MIGRATION_1_2/2_3/3_4`, `allowBackup=false`.
- **Удаление приложения стирает БД.** Обновляться только **установкой поверх**.
- Перед обновлением — жать «Сохранить JSON» (полный бэкап). Восстановление —
  «Восстановить из JSON» (upsert по id, ничего не удаляет, сохраняет createdAt).
- Краш `Room cannot verify data integrity (identity hash)` = схема изменилась
  без поднятия version. Лечение: поднять `version` + добавить миграцию (или, как
  крайность, destructive fallback + восстановление из JSON-бэкапа).
- При добавлении поля в @Entity — **обязательно** version++ и миграция.
- Добавление значения в enum (напр. NAMEDAY) схему НЕ меняет (хранится как TEXT).

## 4. Сборка, окружение, CI
- Распаковывать в короткий ASCII-путь (`C:\ss\`). На кириллице в пути —
  `android.overridePathCheck=true` в gradle.properties (уже стоит).
- `gradle.properties`: `useAndroidX=true`, `disallowKotlinSourceSets=false`,
  `configuration-cache=false`, `overridePathCheck=true`.
- `isMinifyEnabled = true` → нужны `-keep` для классов, создаваемых рефлексией
  (BroadcastReceiver/Service/Activity/Room/model) — уже есть в proguard-rules.pro.
  Без них: `ClassNotFoundException` (был BootReceiver).
- GitHub Actions: только `checkout@v4`, `setup-java@v4`, `upload-artifact@v4`;
  Android SDK и Gradle ставить через wget; везде `working-directory: ss-v1`.
  Запрещено: firebase.bom без json, roborazzi, кастомный signingConfig,
  `actions@v3`, `android-actions/setup-android`.
- `finished` + предупреждения ≠ провал. Действовать только на `failed` + `e:`.

## 5. Правила кода (частые «мины»)
- Что данные, а что UI-текст: роли семьи (Муж/Жена/...), типы — это **данные**
  (enum/строки-ключи), НЕ локализуются. Заголовки авто-событий рисуются меткой
  типа на лету (`calendarDisplayTitle`).
- Enum: `label(context)` для UI, `labelKey()` (стабильный русский) для слоя
  данных. `.name` enum в UI — нельзя, только `.label(context)`.
- `@Composable label()/title()` нельзя звать в некомпозабл-лямбдах/корутинах —
  передавать `Context` и `context.getString(...)`.
- Никаких `database!!` / force-unwrap; даты через `isBefore/isAfter`.
- `resolveActivity()` на Android 11+ = null → `startActivity` в try-catch.
- GoogleMap — только после проверки Google Play Services; `cameraState.animate()`
  в try-catch; `MapProperties(isMyLocationEnabled=...)` только при выданном
  разрешении.
- Строки в UI — только `stringResource`, и сразу во всех 3 strings.xml. `&`→`&amp;`,
  `'`→`\'`. Паритет числа строк ru/en/el обязателен.
- `FlowRow` требует `@file:OptIn(ExperimentalLayoutApi::class)` до `package`.

## 6. Дизайн-система и принципы
- Цвета по смыслу: `primary #4F3DC7` — действия/акценты; `tertiary` — даты/события;
  `error` — просрочка/опасное; `secondary` — второстепенный текст.
- Формы SocialShape: поля/чипы **8**, карточки **16**, bottom sheet **24**,
  аватары/бейджи **50%**. Отступы кратны **4dp**.
- Обнаруживаемость прежде всего: пустое состояние = точка входа («+ Добавить …»,
  а не «Нет данных»); действие — в заголовке блока; один заметный акцент на экран;
  подпись у неочевидных иконок.
- Редактирование — **тапом по блоку**, не мелким карандашом.
- Эргономика: тап-цели ≥48dp, частое — в зоне большого пальца, контент
  скроллится; живую карту не класть в общий скролл (фикс. высота/отдельный режим).
- Дизайн уровня Apple — для **всего** приложения; вести через общие компоненты
  и токены, делать по одному экрану/блоку с пересборкой между.

## 7. Дисциплина QA (каждый ZIP)
- `python3 qa_check.py` — все гарды зелёные (incl. У41–У54: баланс скобок,
  enum существует в Enums.kt, ноль кириллицы в локализованных литералах кроме
  ROLE_DATA_OK, нет дублей `<string>`, классы манифеста существуют, `-keep` при
  минификации, целостность .webp).
- Новый гард — с негативным тестом.
- Скриптовые правки — по уникальным якорям, не `rfind('}')`; после правки
  проверять баланс `{}`/`()` и паритет строк.
- Один источник правды — наш ZIP. Цикл: правка → баланс → qa зелёный →
  пересборка zip → отдать. По одному изменению за раз, с тестом между.

## 8. Принятые решения по продукту (смысловые)
- **«Важный» vs «Ключевой»** — это ступени `ImportanceLevel`
  (обычный→важный→ключевой). Ключевой = топ-приоритетные люди.
- **FORD-«Семья» vs «Смежные люди»** — был дубль (родственники в обоих). Решено:
  FORD «Семья» = связи с семейными ролями; «Связанные люди» в Обзоре = только
  **несемейные**. Роли сохраняются с обеих сторон (firstRole=моя, secondRole=его),
  чтобы связь верно отображалась и в карточке родственника.
- **Событие на нескольких людей** — модель поддерживает (`links` — список); UI
  переведён на мультивыбор (чипы + «Добавить человека»).
- **Подарки — один источник правды** = вкладка «Подарки» (`GiftIdea`,
  3 статуса IDEA→BOUGHT→GIVEN). Из типов заметки убран «Подарок», чтобы не было
  второго несинхронного пути.
- **Мечты** хранятся как заметки типа `PERSONAL_DETAIL` (так их читает блок D) —
  значит мечта может также показаться в ленте личных деталей; особенность модели.
- **«Где познакомились»** — в «Обзоре» (не в «Работе»).
- **Адреса**: рабочие (WORK/OFFICE/BRANCH/LEGAL) → вкладка «Работа», дом и
  прочее → «Связь».
- **Телефоны** дедуплицируются по последним 10 цифрам (чтобы +7/8/пробелы не
  плодили дубли).
- **Даты/время** — только пикерами (`DatePickerField`/`TimePickerField`), не
  ручным вводом. Тип «Именины» (NAMEDAY) добавлен. У дат (ДР/годовщина/именины/
  важная дата) нет кнопки «Выполнено».
- **Инлайн-редактирование Обзора**: все 4 FORD-блока имеют точку входа
  «+ Добавить …» и диалог (интересы — чипы категорий; мечты — текст; семья —
  поиск контакта + роли; работа — поиск компании + должность).

## 10. Карта и публикация (на стороне владельца)
Код карты подключён верно. Чтобы заработала: биллинг в Google Cloud → включить
**Maps SDK for Android** → создать ключ → ограничить ключ **package + SHA-1**
(debug `gradlew signingReport`; release из Play App Signing) + API restriction →
ключ в `local.properties` (не в git) → **ротировать утёкший ключ** → `gradlew
clean assembleDebug`. См. `HOW_TO_ADD_MAPS_KEY.md`.
